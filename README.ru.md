# hass-autoscan

[English](README.md) | **Русский**

[![Открыть Home Assistant и настроить интеграцию MQTT.](https://my.home-assistant.io/badges/config_flow_start.svg)](https://my.home-assistant.io/redirect/config_flow_start/?domain=mqtt)

autoscan — это не кастомная интеграция Home Assistant, а пара
самостоятельных Docker-сервисов, которые общаются с HA через MQTT. Значок
выше просто открывает настройку интеграции MQTT в HA — единственное, что
нужно сделать вручную на стороне HA. После этого сущности RTSP URL/ROI
(см. ниже) [появляются автоматически](#управление-из-home-assistant) через
MQTT Discovery — отдельного шага «установки» самого autoscan не требуется.

CUDA-ускоренное распознавание автомобильных номеров для управления
шлагбаумом/воротами по видео с камеры, разделённое на два независимо
разворачиваемых сервиса, связанных через MQTT — потому что GPU-машина и
хост Home Assistant обычно являются двумя разными физическими машинами:

- **`worker/`** — работает на GPU-машине. Смотрит RTSP-поток с камеры,
  запускает Nomeroff-Net (YOLOv8 + RNN OCR, оптимизирован под
  российские/СНГ номерные форматы) для обнаружения и распознавания
  номеров и публикует каждое обнаружение в MQTT.
- **`client/`** — работает на хосте Home Assistant (или рядом с ним), GPU
  не требуется. Подписывается на эти обнаружения, сверяет их со списком
  разрешённых номеров и вызывает сервис Home Assistant (например,
  switch или script) для открытия ворот — плюс логирует каждое событие
  (SQLite + JPEG-снимок) для последующего аудита.

## Архитектура

```
[GPU-машина]                                     [машина с Home Assistant]
worker/                                           client/
RTSP-камера → FrameReader → NomeroffANPR    MQTT   → MQTTSubscriber → normalize
   → MQTTPublisher  ───────────────────────────────────→ проверка confidence
   (сырой номер, confidence,                             → сверка со списком
    ts, снимок jpeg base64)                              → проверка cooldown
                                                         → HAClient.call_gate()
                                                         → EventLogger (SQLite+снимок)
```

Ворота открываются только если номер **точно** совпадает со списком
разрешённых (после нормализации кириллических/латинских похожих символов)
**и** уверенность OCR (confidence) выше настраиваемого порога; окно
cooldown не даёт одному и тому же проезжающему автомобилю повторно
открывать ворота.

У `worker` есть режим `--debug`, который полностью пропускает MQTT — только
камера + ANPR, распознанные номера выводятся в консоль, снимки сохраняются
локально. Используйте его, чтобы проверить связку камера/ANPR отдельно,
прежде чем настраивать MQTT/HA.

## Требования

**Машина с worker (GPU):**
- NVIDIA GPU, драйверы и
  [nvidia-container-toolkit](https://github.com/NVIDIA/nvidia-container-toolkit)
  (для доступа Docker к GPU).
- Камера с поддержкой RTSP, доступная с этой машины.

**Машина с client** (например, ваш хост Home Assistant):
- Docker (GPU не нужен).
- Доступный отсюда экземпляр Home Assistant с долгоживущим токеном
  доступа (Профиль → Безопасность → Долгосрочные токены доступа) и
  сущностью `switch` или `script`, открывающей ваши ворота.

**Обе машины:**
- Docker + Docker Compose v2.
- Сетевой доступ к общему **MQTT-брокеру** (например, аддону Mosquitto в
  Home Assistant). Этот проект не запускает брокер сам — укажите в
  конфигурации обоих сервисов уже имеющийся у вас брокер.

## Структура репозитория

```
worker/            # GPU-машина
  app/
    camera.py       # чтение RTSP-кадров с переподключением/backoff
    anpr.py         # обёртка над Nomeroff-Net (детекция + OCR номера)
    message.py      # формирует JSON-payload обнаружения для MQTT
    mqtt_publisher.py
    snapshot.py     # локальное сохранение снимков, только для --debug
    config.py
    main.py
  config/config.example.yaml
  Dockerfile
  docker-compose.prod.yml    # обычный запуск: публикует обнаружения в MQTT
  docker-compose.debug.yml   # запуск --debug: только камера+ANPR, без MQTT

client/             # хост HA, GPU не нужен
  app/
    normalize.py    # нормализация текста номера (кириллица/латиница)
    whitelist.py     # точное сравнение со списком разрешённых номеров
    cooldown.py      # подавление повторных срабатываний по одному номеру
    ha_client.py      # REST-клиент Home Assistant (с повторами/backoff)
    eventlog.py       # журнал событий SQLite + хранение JPEG-снимков
    message.py        # разбор JSON-payload обнаружения из MQTT
    mqtt_subscriber.py
    config.py
    main.py
  config/config.example.yaml
  Dockerfile
  docker-compose.yml
```

У каждой стороны свои `tests/` (pytest, GPU и брокер не требуются) и
`requirements.txt`. Они полностью независимы — никогда не запускайте
`pytest` сразу по обоим деревьям; тестируйте раздельно:
`(cd worker && pytest tests/)` и `(cd client && pytest tests/)`.

## Схема MQTT-сообщений

- **Топик**: `mqtt_topic` на обеих сторонах, по умолчанию
  `autoscan/plates/detections` — должен совпадать у worker и client.
- **Payload** (JSON), одно сообщение на каждое сырое обнаружение (без
  фильтрации — всю сверку/пороги делает client):
  ```json
  {
    "schema_version": 1,
    "ts": 1752500000.123456,
    "plate_raw": "А123ВС777",
    "confidence": 0.93,
    "snapshot_jpeg_b64": "<JPEG в base64>"
  }
  ```
- **QoS 1, retain false**. Оба сервиса используют фиксированный
  `mqtt_client_id` и постоянную сессию, поэтому брокер ставит обнаружения
  в очередь, пока одна из сторон кратковременно недоступна.

## Управление из Home Assistant

Worker также публикует сущности [MQTT Discovery](https://www.home-assistant.io/integrations/mqtt/#mqtt-discovery)
(включено по умолчанию, `ha_discovery_enabled: true`), позволяя менять две
вещи прямо из интерфейса HA, без перезапуска:

- Сущность **text** («RTSP URL») — при изменении worker сразу
  переподключается к новому потоку.
- Четыре сущности **number** («ROI x_min/y_min/x_max/y_max») — область
  распознавания, в долях (0–1) от размера кадра. В Nomeroff-Net передаётся
  только эта область, поэтому если направить её только на полосу перед
  шлагбаумом, это одновременно повышает точность (игнорирует посторонний
  трафик/пешеходов) и ускоряет распознавание. По умолчанию — весь кадр
  (`0,0,1,1`).

Эти сущности появляются в HA автоматически, как только worker подключается
к тому же брокеру, что использует HA для discovery (`ha_discovery_prefix`,
по умолчанию `homeassistant`). HA публикует изменения значений с
`retain: true`, поэтому при перезапуске worker переподписка сразу
восстанавливает последние значения, заданные в HA — отдельное хранилище на
стороне worker не нужно.

Режим `--debug` по-прежнему применяет ROI из `config.yaml` (удобно, чтобы
визуально проверить область по сохранённым снимкам перед боевым запуском),
но поскольку он не подключается к MQTT, менять её на лету нельзя —
действует только статическое значение из конфига.

## Видимость обнаружений в Home Assistant

Client также публикует сущности [MQTT Discovery](https://www.home-assistant.io/integrations/mqtt/#mqtt-discovery)
(включено по умолчанию, `ha_discovery_enabled: true`) для последнего
обнаружения, под устройством «Autoscan Client»:

- **Sensor** («Last Scanned Plate») — нормализованный текст номера, с
  сырым текстом OCR, уверенностью и результатом сверки со списком в
  дополнительных атрибутах.
- **Sensor** («Last Detection Time») — время последнего обнаружения.
- **Camera** («Last Plate Snapshot») — снимок ROI из этого обнаружения,
  чтобы видеть, что именно увидела камера.

Все три с `retain: true`, поэтому в HA видны последние известные значения
даже после перезапуска client, и переотправляются заново при каждом
переподключении на случай, если сам брокер перезапустился без retained
сообщений.

## ⚠️ Обязательная настройка безопасности: ACL брокера

Одних логина/пароля MQTT **недостаточно**, как только обнаружения
пересекают границу сети — любой, кто может публиковать в топик
обнаружений, может подделать сообщение с угаданным разрешённым номером и
высокой уверенностью, полностью обойдя камеру и открыв ворота.

**Обязательно настройте ACL на стороне брокера**, ограничивающие топики:
учётные данные worker должны иметь право только **публиковать** в
`mqtt_topic`, а учётные данные client — только **подписываться** на него
— больше никто не должен иметь право публиковать в `mqtt_topic`, иначе
можно подделать обнаружение и открыть ворота. Дополнительно worker нужен
доступ на чтение/запись к своему дереву топиков управления
(`autoscan/<mqtt_client_id>/...`) и запись в префикс discovery HA
(`<ha_discovery_prefix>/#`), для его live-управления RTSP URL/ROI. Client
аналогично нужен доступ на запись в своё дерево топиков
(`autoscan/<mqtt_client_id>/...`) и в префикс discovery — для сущностей
последнего номера/времени/снимка, описанных выше; это менее критично, чем
у worker, поскольку client публикует только state сенсоров для чтения, а
не что-то управляющее камерой или воротами. Для Mosquitto это выглядит
как [файл ACL](https://mosquitto.org/man/mosquitto-conf-5.html):

```
user autoscan-worker
topic write autoscan/plates/detections
topic readwrite autoscan/autoscan-worker/#
topic write homeassistant/#

user autoscan-client
topic read autoscan/plates/detections
topic readwrite autoscan/autoscan-client/#
topic write homeassistant/#
```

(Пользователю встроенной MQTT-интеграции Home Assistant также нужен доступ
к `autoscan/<mqtt_client_id>/+/set` для отправки команд и к
`<ha_discovery_prefix>/#` для получения discovery — обычно это уже
покрывается полным доступом встроенного пользователя аддона Mosquitto.)

TLS в этом проекте не настроен — учётные данные и сообщения передаются в
открытом виде по вашей локальной сети. Это осознанный компромисс для
доверенной домашней сети, а не что-то скрытое — настройте TLS сами, если
ваш брокер находится не в полностью доверенной сети.

## Конфигурация

### Worker (`worker/config/config.example.yaml` → `config.yaml`)

| Поле | Обязательно | По умолчанию | Описание |
|---|---|---|---|
| `rtsp_url` | всегда | — | URL RTSP-потока |
| `sample_fps` | нет | `3` | Кадров в секунду, забираемых из потока |
| `mqtt_broker_host` | в боевом режиме | — | Хост/IP MQTT-брокера |
| `mqtt_broker_port` | нет | `1883` | Порт MQTT-брокера |
| `mqtt_username` / `mqtt_password` | нет | `null` | Учётные данные MQTT (ACL только на публикацию) |
| `mqtt_topic` | нет | `autoscan/plates/detections` | Должен совпадать с топиком client |
| `mqtt_client_id` | нет | `autoscan-worker` | Фиксированный ID для очереди с постоянной сессией |
| `roi_x_min` / `roi_y_min` / `roi_x_max` / `roi_y_max` | нет | `0.0`/`0.0`/`1.0`/`1.0` | Область распознавания, в долях размера кадра; можно менять из HA на лету при включённом discovery |
| `ha_discovery_enabled` | нет | `true` | Публикует описанные выше сущности HA MQTT Discovery |
| `ha_discovery_prefix` | нет | `homeassistant` | Должен совпадать с префиксом discovery вашей интеграции MQTT в HA |

### Client (`client/config/config.example.yaml` → `config.yaml`)

| Поле | Обязательно | По умолчанию | Описание |
|---|---|---|---|
| `mqtt_broker_host` | всегда | — | Хост/IP MQTT-брокера |
| `mqtt_broker_port` / `mqtt_username` / `mqtt_password` / `mqtt_topic` / `mqtt_client_id` | нет | те же значения по умолчанию, что у worker (`autoscan-client` для client id) | Должны указывать на тот же брокер/топик, что и worker |
| `ha_url` | в боевом режиме | — | Базовый URL вашего экземпляра Home Assistant |
| `ha_token` | в боевом режиме | — | Долгоживущий токен доступа |
| `ha_domain` / `ha_service` / `ha_entity_id` | в боевом режиме | — | например `switch` / `turn_on` / `switch.gate_relay` |
| `allowed_plates` | в боевом режиме | `[]` | Разрешённые номера (кириллица/латиница нормализуются перед сравнением) |
| `cooldown_seconds` | нет | `60` | Подавляет повторные срабатывания ворот для одного и того же номера |
| `confidence_threshold` | нет | `0.85` | Минимальная уверенность OCR для признания совпадения |
| `dry_run` | нет | `true` | Если true — сверка/логирование работают как обычно, но Home Assistant не вызывается |
| `ha_discovery_enabled` | нет | `true` | Публикует сущности HA MQTT Discovery для последнего номера/времени/снимка, описанные выше |
| `ha_discovery_prefix` | нет | `homeassistant` | Должен совпадать с префиксом discovery вашей интеграции MQTT в HA |

Оба файла `config.yaml` в `.gitignore` — в них хранятся учётные данные, не
коммитьте их.

## Быстрый старт (деплой)

**1. На GPU-машине сначала проверьте камеру + распознавание номеров**,
прежде чем настраивать MQTT/HA:

```bash
cd worker
cp config/config.example.yaml config/config.yaml   # заполните хотя бы rtsp_url
docker compose -f docker-compose.debug.yml up --build
```

Ищите в логах строки вида `[debug] plate=... confidence=...` и проверьте
`data/snapshots/` на предмет соответствующих JPEG-файлов.

**2. Настройте ACL вашего MQTT-брокера** (см. раздел безопасности выше),
затем заполните поля `mqtt_*` у worker и полную конфигурацию client.

**3. На машине с client сначала запустите в режиме `dry_run`**
(включён по умолчанию):

```bash
cd client
cp config/config.example.yaml config/config.yaml   # заполните mqtt_*, ha_*, allowed_plates
docker compose up --build
```

**4. Запустите worker в боевом режиме** (публикация в MQTT вместо
`--debug`):

```bash
cd worker
docker compose -f docker-compose.prod.yml up -d --build
```

Проверьте `data/events.sqlite3` и `data/snapshots/` на стороне client —
там должны появиться ожидаемые события: разрешённый автомобиль должен
показать `matched=1` с `ha_call_result`, всё ещё равным `NULL`
(пропущено из-за `dry_run`).

**5. Переходите в боевой режим**: установите `dry_run: false` в
`config.yaml` client и перезапустите его. Теперь разрешённый номер должен
вызывать настроенный сервис Home Assistant и открывать ворота.

## Замечания по безопасности работы

- Управление воротами по умолчанию «безопасно к отказу»: неоднозначные
  или низкоуверенные распознавания, а также всё, что не совпало со
  списком разрешённых точно, логируются, но никогда не открывают ворота.
- Каждое обнаружение (совпавшее или нет) записывается в
  `data/events.sqlite3` на стороне client вместе со снимком — это
  позволяет позже проверить ложные срабатывания/пропуски.
- Если RTSP-поток обрывается, worker повторяет попытки с задержкой
  (backoff). Если не проходит вызов HA, client тоже повторяет попытки.
  Ни один из сервисов не падает из-за этого.
- MQTT-сообщения используют QoS 1 и постоянные сессии, поэтому
  кратковременный сетевой сбой или перезапуск client не приводит к
  незаметной потере обнаружений — но см. требование про ACL брокера выше:
  это не заменяет защиту топика.

## Разработка

Вся чистая логика каждого сервиса покрыта тестами и не требует GPU, камеры
или брокера:

```bash
python3 -m venv .venv
.venv/bin/pip install pytest pyyaml requests requests-mock opencv-python-headless paho-mqtt

cd worker && ../.venv/bin/pytest tests/ -v && cd ..
cd client && ../.venv/bin/pytest tests/ -v && cd ..
```

Разбор реального вывода Nomeroff-Net в `worker/app/anpr.py` и реальное
поведение RTSP в `worker/app/camera.py` можно полностью проверить только
на машине с доступным GPU и камерой — см. комментарии в `anpr.py` о том,
что стоит перепроверить при первом реальном развёртывании. Для
сквозного (end-to-end) теста передачи данных без GPU направьте оба
сервиса на временный локальный брокер
(`docker run -p 1883:1883 eclipse-mosquitto`) и опубликуйте тестовое
обнаружение через `MQTTPublisher`, чтобы убедиться, что весь путь —
разбор → сверка со списком → вызов HA в dry-run → запись в SQLite/снимок —
работает корректно.

## Известные ограничения / дальнейшие шаги

- Одна камера, одни ворота, один MQTT-топик — пространства имён для
  нескольких камер пока нет.
- Список разрешённых номеров статичен и хранится в `client/config.yaml`;
  горячей перезагрузки или управления списком из HA пока нет.
- ROI — это один прямоугольник, а не произвольный полигон/маска.
- TLS для MQTT-соединения не настроен (см. раздел безопасности).
- Разбор вывода пайплайна в `NomeroffANPR` основан на документированном
  API Nomeroff-Net и не был проверен на реальной модели — сверьте его с
  фактическим выводом установленной у вас версии, прежде чем доверять
  этому в боевой эксплуатации.
